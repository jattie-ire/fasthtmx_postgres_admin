# Log Viewer Quick Reference

## Overview

The Log Viewer allows users to browse, search, and analyze log files generated by scripts. Logs are automatically discovered from configured directories and displayed organized by script name.

**URL**: `http://your-server:8000/logs`  
**Permission Required**: `run_scripts` (same as script execution)

---

## Configuration

### Basic Setup

In `config.toml`:

```toml
[scripts.log_config]
"Script Name" = { directory = "/path/to/logs", pattern = "*.log", display = true }

[scripts.log_display]
limit = 5
max_width = 1200
no_wrap = true
```

### Configuration Options

#### `[scripts.log_config]`

Define where to find logs for each script:

```toml
[scripts.log_config]
"Daily Backup" = { 
    directory = "/var/log/backups",      # Where logs are stored (required)
    pattern = "backup_*.log",            # Glob pattern to match (required)
    display = true                       # Show in log viewer (required)
}
```

**Fields:**
- `directory`: Absolute or relative path to search for logs
- `pattern`: Glob pattern (e.g., `*.log`, `app_*.log`, `debug_log_*.log`)
- `display`: Boolean; if `false`, logs won't appear in viewer

#### `[scripts.log_display]`

Global settings for log viewer:

```toml
[scripts.log_display]
limit = 5           # Number of most recent logs to show per script (default: 5)
max_width = 1200    # Maximum width of viewer modal in pixels (default: 1200)
no_wrap = true      # Disable line wrapping, enable horizontal scrollbar (default: true)
```

**Options:**
- `limit` — Maximum number of most recent logs shown per script. If a script runs 1000+ times, this prevents slow loading. (default: 5)
- `max_width` — Maximum width of the log viewer modal in pixels. Adjust for your screen size. (default: 1200)
- `no_wrap` — If `true`, log lines won't wrap and will have a horizontal scrollbar for long lines. If `false`, lines wrap normally. (default: true)

## Usage

### 1. Navigate to Log Viewer

Click "📋 View Logs" in the sidebar, or visit `/logs` directly.

### 2. Browse Logs by Script

- Logs are organized by script name in collapsible sections
- Each section shows: **Script Name** | **[N log(s)]**
- Click to expand/collapse sections
- Most recent logs shown first

### 3. View Log Details

1. Find the log you want to see
2. Click the **📂 View** button (right side of row)
3. Modal opens with full log content

### 4. Understanding the Display

#### Log Information

For each log file, you see:
- **Filename** — Original filename (e.g., `debug_log_1782986069.log`)
- **Date & Time** — Human-readable timestamp (e.g., `2026-07-02 09:54:29`)
- **Size** — File size in KB
- **Action** — View button to open log

#### Log Content

When viewing a log, you'll see:

**Syntax Highlighting:**
- **Blue text** = Timestamps (ISO 8601 format, e.g., `2026-07-02 09:54:29`)
- **Orange text** = File and function names (e.g., `app.py:main:process_data`)
- **Cyan text** = Numeric values - integers and floats (e.g., `1234`, `3.14159`)
- **Red text** = ERROR, CRITICAL, FATAL log levels (highlighted with background)
- **Gold text** = WARNING, WARN log levels (highlighted with background)
- **Green text** = INFO log level (highlighted with background)
- **Purple text** = DEBUG log level (highlighted with background)
- **Gray text** = TRACE log level (highlighted with background)
- **Light cyan text** = Key=value pairs (e.g., `color=red`, `count=42`)

**Display Modes:**

Configured via `no_wrap` setting:

- **`no_wrap = true`** (default): Lines don't wrap. Long log lines scroll horizontally with scrollbar. Best for structured logs with consistent formatting.
- **`no_wrap = false`**: Lines wrap to fit container width. Good for text-heavy logs that don't need horizontal scrolling.

## Examples

### Example 1: Debug Script Logs

**config.toml:**
```toml
[scripts.log_config]
"Background Process" = { directory = "../logs", pattern = "debug_log_*.log", display = true }

[scripts.log_display]
limit = 5
```

**Result:** Log Viewer shows up to 5 most recent debug logs from `../logs/debug_log_*.log`

### Example 2: Multiple Scripts

```toml
[scripts]
"Daily Backup" = "/scripts/backup.sh"
"Hourly Sync" = "/scripts/sync.sh"

[scripts.log_config]
"Daily Backup" = { directory = "/var/log/backups", pattern = "backup_*.log", display = true }
"Hourly Sync" = { directory = "/var/log/sync", pattern = "sync_*.log", display = true }

[scripts.log_display]
limit = 10
```

**Result:** Two sections in Log Viewer; each shows 10 newest logs

### Example 3: Filename Patterns

Different glob patterns to match different naming schemes:

```toml
# Match logs like: app_2024_06_11.log, app_2024_06_12.log, etc.
"App Logs" = { directory = "/var/log/app", pattern = "app_*.log", display = true }

# Match all .log files in directory
"All Logs" = { directory = "/var/log/all", pattern = "*.log", display = true }

# Match logs like: debug_1234567890.log (epoch timestamp)
"Debug Logs" = { directory = "/logs", pattern = "debug_*.log", display = true }

# Match nested patterns
"Backups" = { directory = "/backups", pattern = "**/backup*.log", display = true }
```

## Troubleshooting

### "No log files found"

**Cause**: Either:
- `[scripts.log_config]` not configured in `config.toml`
- Log directory doesn't exist
- Pattern doesn't match any files

**Fix**:
```bash
# Verify config
python deploy_tools.py validate-config

# Check directory exists
ls -la /var/log/backups/

# Check files match pattern
ls -la /var/log/backups/backup_*.log
```

### Logs appear in wrong order

**Cause**: Filenames don't sort chronologically (e.g., "log_1", "log_2", ... "log_10")

**Fix**: Rename to sortable format
- Use epoch timestamps: `log_1718125200.log`
- Use ISO dates: `log_2024_06_11.log`
- Use zero-padded numbers: `log_0001.log`, not `log_1.log`

### Log content not displaying correctly

**Cause**: Character encoding or very large file

**Fix**:
- Ensure log files use UTF-8 encoding
- Extremely large logs (>50MB) may be slow to load
- Consider splitting into multiple smaller log files

### Permission denied

**Cause**: User doesn't have `run_scripts` permission

**Fix**: Ask admin to grant `run_scripts` permission in user management

## Performance Notes

- **Log discovery** happens at page load (scans filesystem once)
- **Large log files** may take a few seconds to load (displayed in modal)
- **Pattern matching** uses standard glob patterns (efficient)
- **Sorting** by epoch timestamp in filename (no database queries)

For large deployments:
- Keep log directories on fast storage
- Clean up old logs periodically (`find /var/log/logs -mtime +30 -delete`)
- Consider `limit = 3` or `limit = 5` instead of `limit = 20`

## API Endpoints

For developers integrating with the log viewer:

**List all logs:**
```bash
GET /api/logs
# Returns JSON: { "Sync": [...], "Backup": [...] }
```

**Read specific log file:**
```bash
GET /api/logs/var/log/backups/backup_123456.log
# Returns JSON: { "success": true, "content": "log file contents..." }
```

Both endpoints require `run_scripts` permission.

## Security

- ✅ User permission checks on all endpoints
- ✅ Log files served as plain text (safe, no code execution)
- ✅ File path validation prevents directory traversal attacks
- ✅ Only configured directories are accessible

Logs are **not** encrypted in transit. Use HTTPS in production.

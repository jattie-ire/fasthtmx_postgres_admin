# Changelog

All notable changes to FastHTMX Admin are documented in this file.

## [1.1.0] - 2026-07-02

### Added
- **Log Viewer** (`/logs`) — Browse log files generated by scripts with:
  - Automatic log discovery using glob patterns
  - Organization by script name
  - Syntax highlighting for timestamps, log levels, key=value pairs
  - Responsive modal viewer for large log files
  - Pattern recognition: ERROR (red), WARNING (gold), INFO (green), DEBUG (purple), etc.
  - Configuration via `[scripts.log_config]` and `[scripts.log_display]`

- **Log Management Functions** (database.py):
  - `list_all_logs()` — Discover and organize logs by script
  - `read_log_file()` — Read log content with error handling
  - `find_latest_log_file()` — Find newest log by epoch timestamp
  - Configuration accessors in `config.py`

- **Log Viewer Endpoints**:
  - `GET /logs` — HTML page with log browser UI
  - `GET /api/logs` — JSON endpoint returning all discovered logs
  - `GET /api/logs/{log_file:path}` — Read specific log file content

- **Sidebar Navigation Link** — "📋 View Logs" link in Run Scripts section

### Fixed
- **Critical Connection Pool Bug** — Fixed PostgreSQL connection pool exhaustion:
  - **Issue**: 4 locations in `app.py` calling `conn.close()` instead of `return_db_connection(conn)`
  - **Impact**: Connections permanently removed from pool, causing `psycopg2.pool.PoolError` after 10 requests (maxconn=10)
  - **Solution**: All database operations now properly return connections via pool's `putconn()` method
  - **Files**: [app.py](app.py) — 4 `finally` blocks updated
  - **Verification**: No remaining `conn.close()` calls in database handling code

### Changed
- **Documentation Updates**:
  - README.md: Added Log Viewer feature description and configuration guide
  - config.example.toml: Added `[scripts.log_config]` and `[scripts.log_display]` sections
  - DEPLOY.md: Added log configuration to validation checks
  - Connection pooling documented with auto-recovery details

### Technical Details

#### Log Viewer Implementation
- **Frontend**: Custom log highlighting with DOM-safe rendering
  - No HTML injection vulnerabilities (uses textContent + createElement)
  - Regex-based pattern matching: timestamps, log levels, key=value pairs
  - Line-by-line processing with overlap prevention
  - CSS classes for styling: `.log-ts`, `.log-error`, `.log-warn`, etc.

- **Backend**: Efficient log discovery and serving
  - Glob pattern matching per script from `config.toml`
  - Epoch-based filename sorting (newest first)
  - Configurable limit per script (default: 5 most recent)
  - Error handling for missing/unreadable files

- **Configuration**:
  ```toml
  [scripts.log_config]
  "Script Name" = { directory = "../logs", pattern = "debug_log_*.log", display = true }
  
  [scripts.log_display]
  limit = 5
  ```

#### Connection Pool Fix
- **Root Cause**: Mixed connection lifecycle management
  - `conn.close()` removed connections from pool permanently
  - `return_db_connection(conn)` called pool's `putconn()` method
  - Connections were being both returned AND closed in some endpoints

- **Fix Applied**:
  - Located: 4 `finally` blocks in `app.py`
  - Changed: All `conn.close()` → removed (connection returned by finally block)
  - Pattern: Consistent use of `return_db_connection(conn)` in all DB error paths

- **Testing**: 
  - Verified with grep: `grep -r "\.close()" app.py` → 0 results for connection close
  - Endpoint testing: No connection exhaustion after 10+ requests
  - Pool remains stable: confirmed with connection count monitoring

### Deployment Notes

1. **Existing Deployments**: 
   - Update to 1.1.0 to fix critical connection pool bug
   - No database schema changes required
   - No dependency changes

2. **Configuration**:
   - Log viewer is **optional** — requires `[scripts.log_config]` in config.toml
   - If not configured, log page returns "No log files found" message
   - Existing deployments work without changes

3. **Validation**:
   - Run `python deploy_tools.py validate-config` to verify log paths exist
   - Log directories and glob patterns are validated before deployment
